# GUI 参考手册

`gui/gui.py` 是 100 格国际跳棋的 Tkinter 图形界面。它通过 `interface.DraughtsEnv` 调用 C 引擎，不在 GUI 中重实现棋规。

## 快速开始

在项目根目录执行：

```bash
make interface
PYTHONPATH=interface:. python3 gui/gui.py
```

启动后弹出"新建对局"窗口，选择黑白双方决策源即可开始。

选择监督模型或 MCTS 时，可在“模型设备（双方共用）”中选择 `cpu` 或当前可用的 `cuda:N`。CPU 模式下 FP16 选项禁用；启动日志记录模型实际使用的设备。关闭新建对局窗口会取消本次配置并回到原对局。

新建对局中的“先手方名称（棋谱）”“后手方名称（棋谱）”默认填“先手方”“后手方”，可替换为队伍或程序名称。

## 决策源

| 选项 | 说明 | 需选文件 |
|------|------|---------|
| 人类 | 鼠标点击走子 | — |
| 随机AI | 随机选择合法走法 | — |
| AlphaBeta AI | Alpha-Beta depth=2 搜索 | — |
| 监督模型AI | 加载 `CandidateMoveNet`，greedy 推理 | `.pt` checkpoint |
| MCTS AI | MCTS + 网络引导搜索 | `.pt` checkpoint + 可选 `.yaml` 配置 |

MCTS AI 选择 checkpoint 后会弹出可选的 YAML 配置文件选择框（默认使用 `draughts/config/mcts.yaml`）。

## 功能

### 对局交互
- 七种决策源任意组合
- 棋盘显示含棋位编号，支持 180° 旋转视角
- 点击棋子 → 高亮合法落点 → 点击落点执行
- 多路线歧义时侧边栏显示候选动作，双击确认
- 左侧棋谱面板
- 侧边栏：行棋方、合法动作数、终局状态、最近动作
- 合法动作列表（表格视图）
- 彩色日志（信息/动作/警告/错误/终局）
- 按钮：新建对局、重开本局、悔棋、旋转棋盘
- AI 控制：暂停/继续自动走棋、手动触发单步

### 搜索与判负控制

- 暂停时可点击“AI走一步”，完成一次落子后仍保持暂停。
- 暂停、重开、悔棋或关闭窗口会发出搜索取消信号；取消在搜索节点或网络推理调用之间生效，正在进行的单次推理结束后退出。
- 每次搜索使用独立局面快照，同一时刻只运行一个走棋任务；替代任务等待旧任务退出，旧结果不会用于新局面。
- 后台线程通过队列交回结果，所有 Tk 操作与最终落子均由主线程执行。
- 非法操作、不可走操作、AI 异常或 AI 返回非法/空走法时，弹出判负确认窗口。“确定（判负）”结束对局并判当前方负；“取消（重新落子）”保留局面并清除选择。
- AI 异常后自动走棋暂停，取消判负后可以点击“AI走一步”重试，也可继续自动走棋；按 Escape 或关闭判负窗口等同于取消。

### 回归测试

`make gui-test` 无需图形显示器即可测试单步、取消、旧结果拦截、判负确认/取消及设备传递；此测试已纳入 `make all-python-test`。

### TXT 棋谱记录与导出

棋谱面板按双方各走一步为一行显示，例如 `1. 20-24 33-29`。棋位为固定的 1–50 编号，旋转棋盘或轮到白方时不改变编号；1 号位在顶行左侧第二格，5 号位在右上角，46 号位在左下角，50 号位在底行右侧第二格。此映射与提供的打谱软件说明图 1 一致。

普通走子用 `-`，吃子用 `x`，保留完整连跳落点，例如 `34x23x14`；1–9 号棋位补零，如 `03-09`。悔棋、曲线回溯和重开会同步更新记录。

点击棋谱面板下方“导出棋谱”，选择 `.txt` 文件位置。文件使用 UTF-8 BOM 与 CRLF 换行，包含以下内容：

```text

时间：2026.10.18
先手：1
先手方：先手方
后手方：后手方
结果：*

1. 20-24 33-29
2. 24x33
*
```

`先手：1` 对应本项目从上方 1–20 号位出发的黑方，与示例中的红方位置对应。结果在头部和末行各写一次：先手胜 `1-0`、后手胜 `0-1`、和棋 `1/2-1/2`、未结束 `*`。确认判负也会记录真实胜方，不增加虚构走法；取消判负不改变棋谱。此处只提供和棋结果的格式支持，不增加和棋判定规则。

导出保存打开文件选择窗口时的对局快照，即使 AI 在选择文件期间继续走棋，文件中的走法和结果仍保持一致。写入失败时不会覆盖已有棋谱。尚未在提供说明对应的 Windows 软件中实机导入验证。

### 引擎分析可视化（v1.8 新增）

当对局中至少一方为 AI（监督模型或 MCTS）时，界面会实时展示神经网络的决策过程：

**评估条（Eval Bar）**
- 棋盘左侧的竖条，直观显示当前局面的胜率预估
- 上方深色区域 = 黑方胜率，下方浅色区域 = 白方胜率
- 金色分割线指示网络估值，中央虚线为均势参考线
- 百分比标签显示当前行棋方的预估胜率
- 数据来源：网络的 Value Head 输出（tanh ∈ [-1, 1]）

**走法概率列**
- 合法动作列表中新增"概率"列
- 显示每个走法被 AI 选中的概率（百分比）
- 最优走法以黄色高亮标记
- 候选走法（已选棋子的合法走法）以绿色高亮
- 数据来源：MCTS 的 visit count 分布（MCTS AI）或 softmax(policy_logits)（监督模型 AI）

**引擎分析面板**
- 位于侧边栏的"引擎分析"区域
- 估值（Value）：当前局面网络估值，含黑方胜率百分比
- 搜索量（Search）：MCTS 模拟次数和 c_puct 参数（或 AlphaBeta 搜索深度）
- 首选（Best Move）：AI 最倾向的走法及其概率
- 人类对局或无 AI 参与时显示 "—"

### 估值曲线（v1.10 新增）

棋谱面板下方的折线图，实时追踪对局估值变化。

- **数据来源**：对局中至少一方为 AI（监督模型或 MCTS）时，每步走完后自动推理当前局面的估值
- **混合采集**：AI 决策时免费记录估值；人类走棋后用 AI 的模型补推理一次，人机对弈也能获得完整曲线
- **Y 轴**：黑方胜率 0%–100%，50% 线为均势参考虚线
- **X 轴**：步数（ply），横向滚动条支持长对局
- **数据点颜色**：黑优段深色 → 均势中性灰 → 白优段浅色
- **当前步标记**：金色竖虚线指示最新估值位置

**交互**：
- 点击曲线上任意数据点 → 自动暂停对弈并回溯到对应步数
- 回溯后暂停按钮变红色，点击"继续AI"可从此位置继续
- 最大保留 300 个点（约 150 步对局），超出的旧数据自动丢弃
- 纯人机对弈（无 AI 参与）时曲线显示 "无 AI 参与"

### 引擎分析面板增强（v1.12）

引擎分析面板从 3 列扩展为 4 列，新增**搜索修正**列：显示网络原始估值 → MCTS 搜索后的修正估值，展示搜索是否"纠正"了网络的直觉。仅 MCTS AI 走棋时有效；其余情况显示 "—"。

### 系统监控（v1.12 新增）

棋盘下方的实时硬件资源监控面板：

- **左侧 CP​U 侧**：CPU 总利用率、系统内存、进程 CPU
- **右侧 GPU 侧**：GPU 利用率、显存占用、GPU 温度
- 每行：中文标签 + 水平条形图（绿→黄→红渐变）+ 实时数值
- 条形图带动态过渡动画（250ms ease-out）
- **无新依赖**：CPU/内存读 `/proc`，GPU 读 `nvidia-smi` + `torch.cuda`
- 每秒刷新，始终运行
- 无 GPU 时右侧显示 "无 GPU"

### 暂停按钮颜色提示（v1.10 新增）

- **绿色**：AI 正常运行中（可暂停）
- **红色**：AI 已暂停（可恢复）

### 数据来源说明

| AI 类型 | 估值来源 | 概率来源 |
|---------|---------|---------|
| MCTS AI | 网络根节点 Value Head 输出 | MCTS visit count 归一化分布 |
| 监督模型 AI | 网络 Value Head 输出 | softmax(policy_logits) |
| AlphaBeta AI | —（仅显示搜索深度） | — |
| 随机 AI / 人类 | — | — |

## 操作

1. 启动 → 选择双方决策源（需 checkpoint 的 AI 会弹出文件选择框）
2. 人类方：点击棋子选中 → 点击高亮落点执行
3. 双击右侧动作列表可指定完整路线（王的多落点歧义）
4. 点击"悔棋"撤销上一步
5. 点击"旋转棋盘"切换 180° 视角
6. 点击"暂停AI"/"继续AI"控制 AI 自动走棋（绿色=运行中，红色=已暂停）
7. 点击工具栏右侧的语言按钮（"English"/"中文"）切换界面语言
8. 点击估值曲线上的数据点 → 自动暂停并回溯到对应步数

## 语言切换（v1.9 新增）

界面支持中文/英文即时切换，无需重启。点击工具栏右侧的语言切换按钮即可。

- 所有静态标签（窗口标题、按钮文字、表格列标题、状态面板等）立即更新
- 日志消息、状态变量、分析面板数据跟随当前语言显示
- 旧日志不回溯翻译，新日志使用当前语言
- 对话框（新建对局）每次打开时使用当前语言
- 翻译数据集中在 `_TRANSLATIONS` 字典中，新增字符串只需添加一条包含 `zh`/`en` 的条目

## 架构

```
gui/
├── __init__.py
├── gui.py                     # 入口（设置 sys.path 后委托给 app.main()）
├── app.py                     # DraughtsApp 主窗口 + 布局 + 回调编排
├── game_controller.py         # GameController 对局状态机
├── agents_local.py            # Human / Random / AlphaBeta / Supervised / MCTS
├── protocol.py                # PlayerAnalysis（数据传递对象）
├── i18n.py                    # 翻译表 _TRANSLATIONS + _tr_static()
├── utils.py                   # 常量 + 棋盘/走法辅助函数
├── fonts.py                   # CJK 字体发现与注册（多后端回退）
├── widgets/
│   ├── __init__.py
│   ├── board.py               # BoardView（棋盘绘制、点击交互）
│   ├── eval_bar.py            # EvalBar（估值竖条）
│   ├── value_curve.py         # ValueCurve（估值曲线 + 点击回溯）
│   └── hardware_monitor.py    # HardwareMonitor（CPU/GPU 实时图表）
└── README-gui.md
```

**依赖方向（自上而下，无循环）：**
```
i18n  fonts  utils  protocol       ← 零外部依赖
  ↓      ↓      ↓      ↓
widgets/  agents_local             ← 纯展示 / AI 代理
    ↓         ↓
game_controller                    ← 对局状态机
    ↓         ↓
  app.py                           ← 主窗口编排
    ↓
gui.py                             ← 入口
```

GUI 不实现棋规——所有动作通过 `action_id → env.step(action_id)` 交给 C 引擎执行。悔棋使用动作历史重放实现。

分析数据的传递路径：
```
Agent.select_action()
  → agent.last_value / agent.last_policy_logits / agent.last_result
  → Player.last_analysis (PlayerAnalysis dataclass)
  → GameController.last_player_analysis()
  → DraughtsApp.update_eval_bar() / update_move_list() / update_search_stats()
```

### 模块职责

| 模块 | 职责 | 设计要点 |
|------|------|---------|
| `protocol.py` | `PlayerAnalysis` 数据结构 | 纯数据类，零依赖。本地 AI 和未来云端 AI 共用同一数据结构 |
| `agents_local.py` | 5 种 Player + `GuiEnvAdapter` | 统一的 `choose_move()` 接口。云端正交替换：新增 `agents_remote.py` 实现相同接口即可 |
| `widgets/` | 4 个独立视图组件 | 只接收数据并渲染，不关心数据来自本地还是云端 |
| `game_controller.py` | 对局状态机 | 通过 duck-typing 调用 Player，不依赖具体 Agent 实现 |
| `app.py` | 主窗口布局 + 回调 | 粘合各模块，处理用户交互和语言切换 |
| `fonts.py` | CJK 字体管理 | 独立模块，被 `app.py` 在启动时调用一次 |
| `i18n.py` | 翻译字典 | 纯数据，所有 UI 字符串的单一来源 |

## 中文字体（Linux）

Linux 下 Conda 自带的 Tk 通常是 **noxft** 编译版本，无法使用系统安装的现代 Unicode 字体（如 Noto Sans CJK），只能看到少量 X11 核心位图字体。GUI 启动时会自动检测并适配：

1. 尝试 fontconfig 路径（Xft Tk）
2. 尝试 fontconfig 注册捆绑的 `DroidSansFallbackFull.ttf`
3. **（新增）** 尝试通过 X11 font path 加载系统黑体（文泉驿微米黑、Noto Sans CJK），这些无衬线字体比 X11 核心宋体圆滑得多
4. 尝试 X11 font path 注册捆绑的 `DroidSansFallbackFull.ttf`
5. 回退到 X11 核心宋体（`song ti`）

**推荐的根治方案**：将 Conda 的 Tk 替换为 Xft 版本，这样能直接使用系统所有 CJK 字体，渲染质量最佳：

```bash
conda install -c conda-forge "tk=8.6.13=xft_*"
```

可通过一行命令自查当前环境：

```bash
echo "会话:$XDG_SESSION_TYPE Tk字体:$(python3 -c 'import tkinter;r=tkinter.Tk();n=len(r.tk.call(\"font\",\"families\"));r.destroy();print(n)')个 Xft:$(ldd $(python3 -c 'import tkinter;print(tkinter._tkinter.__file__)') 2>/dev/null|grep -cq libXft&&echo 是||echo 否)"
```

- **Xft=是 + 字体数 >200**：现代字体路径正常，CJK 渲染完美
- **Xft=否 + 字体数 ~60**：noxft Tk，GUI 自动回退到 X11 位图字体

字体注册通过 `xset +fp` 实现（依赖 `xfonts-utils`），仅在当前 X 会话有效，注销后自动还原。

## 限制

- 仅支持单机对局，不支持网络对战
- 支持 TXT 棋谱导出；暂不支持棋谱导入与崩溃恢复
- 使用点击选择而非拖拽
- 赛事和棋协商与拒和后的 40 步流程暂不实现，已记录在 `PROGRESS.md`；GUI 当前没有自动和棋或步数截断
- PDN 导出、自动存档恢复后续实现
