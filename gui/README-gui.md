# GUI 使用手册

本地棋盘支持人人、人机与 AI 对战。比赛流程见 [比赛操作手册](../docs/competition.md)，规则和棋位编号见 [规则说明](../SPEC.md)。

## 启动与对局设置

在项目根目录、已安装依赖的环境中执行：

```bash
make interface
PYTHONPATH=interface:. python3 gui/gui.py
```

启动后在“新建对局”中选择双方类型：

| 类型 | 决策方式 | 所需文件 |
|---|---|---|
| 人类 | 鼠标选择合法走法 | 无 |
| 随机 AI | 随机选择合法走法 | 无 |
| AlphaBeta AI | AlphaBeta 搜索 | 无 |
| 监督模型 AI | 神经网络直接选择评分最高的合法走法 | `.pt` 模型 |
| MCTS AI | 神经网络引导 MCTS 搜索 | `.pt` 模型；可选搜索配置 |

MCTS 配置选择窗口取消后使用 `draughts/config/mcts.yaml`。模型权重不随仓库提供。

使用模型 AI 时，可选择 `cpu` 或当前进程可见的 `cuda:N`。双方模型共用所选设备，日志记录实际模型设备；CPU 模式禁用 FP16。FP16 与编译为可选推理设置，效果及首次等待时间依赖所用设备和模型。

棋谱名称默认分别为“先手方”“后手方”，可编辑为队伍或程序名称。黑方始终先手。关闭新建对局窗口会取消本次配置并返回原对局。

## 走棋与对局控制

- 点击棋子，再点击高亮落点执行走法。存在多条完整吃子路线时，可在动作列表核对路径并双击选择。
- “暂停AI”停止后续自动走棋；暂停时点击“AI走一步”执行一次，完成后仍保持暂停。“继续AI”恢复自动走棋。
- “悔棋”撤销上一步；“重开本局”回到初始局面。
- “旋转棋盘”切换 180° 视角，不交换双方身份，不改变棋位编号。
- 点击估值曲线中的数据点可暂停并回溯到对应位置；从该位置继续时，棋谱按当前分支更新。
- “English”或“中文”切换界面语言。新日志使用所选语言，已有日志不回溯翻译。

暂停、悔棋、重开或关闭窗口会请求取消搜索。取消在搜索节点或网络推理调用之间生效，正在进行的单次推理结束后退出。搜索使用独立局面快照，旧任务结果不会应用到新的局面。

## 判负确认

非法操作、不可走操作、AI 异常或 AI 返回非法/空走法时，会弹出判负确认窗口：

| 选择 | 处理 |
|---|---|
| 确定（判负） | 当前行棋方判负，对局结束 |
| 取消（重新落子） | 保留棋局与棋谱，清除选择后重新落子 |
| Escape 或关闭确认窗口 | 等同于取消 |

AI 异常后自动走棋暂停。取消判负后可点击“AI走一步”重试，或恢复自动走棋。正式比赛按现场裁定选择。

## TXT 棋谱格式

棋谱面板按双方各走一步为一行显示。点击面板下方“导出棋谱”选择保存位置；文件采用 UTF-8 BOM 和 CRLF 换行，开头保留一个空行。

```text

时间：2026.10.18
先手：1
先手方：先手方
后手方：后手方
结果：*

1. 20-24 33-29
2. 24x33
*
```

编号固定为 1–50，1–9 补零；普通移动使用 `-`，吃子使用 `x`，连跳保留全部落点，如 `34x23x14`。每行记录一对走法，最后只有先手走法时也会保留。

`先手：1` 表示本项目从上方 1–20 号位出发的黑方，对应所提供打谱软件中的上方红方。1 号位在顶行左侧第二格，5 号位在右上角，46 号位在左下角，50 号位在底行右侧第二格。旋转显示或白方行棋都不会改变输出编号。

| 结果 | 标记 |
|---|---|
| 先手胜 | `1-0` |
| 后手胜 | `0-1` |
| 和棋格式 | `1/2-1/2` |
| 尚未结束 | `*` |

结果在头部和末行各写一次。确认判负记录真实胜方，不增加虚构走法；取消判负不改变棋谱。当前仅支持和棋结果的格式表示，GUI 尚无协商和棋结果录入或自动和棋判定。

悔棋、曲线回溯和重开会同步更新棋谱。导出对应打开保存窗口时的对局快照；若 AI 在选择文件期间继续走棋，文件中的走法与结果仍保持一致，但不包含之后的新走法。文件以临时文件写入后替换目标，写入失败时保留原有棋谱。

已对照参考说明核对编号，并通过引擎复盘两份样例。尚未在该 Windows 打谱软件中实机导入验证。

## 分析与监控

| 区域 | 显示内容 |
|---|---|
| 对局状态 | 当前行棋方、合法动作数、终局及最近走法 |
| 合法动作列表 | 完整走法、候选路线，以及可用的模型或搜索分布 |
| 评估条 | 网络对局面的估值，经界面换算为百分比显示 |
| 引擎分析 | 网络估值、搜索参数、首选走法；MCTS 还显示搜索后的估值修正 |
| 估值曲线 | 按半回合记录的黑方视角估值，支持点击回溯 |
| 系统监控 | 可读取的 CPU、内存及 GPU 数据；依赖系统提供相应信息 |
| 日志 | 模型加载、实际设备、走法、异常和终局消息 |

监督模型的走法分布来自 policy logits 的 softmax，MCTS 的分布来自搜索访问次数归一化。网络估值及其百分比是分析参考，不是经过校准的实际胜率。没有模型分析数据时，对应区域显示空缺或“—”。

曲线最多保留 300 个点，较早的数据会移出显示；完整棋谱与曲线显示容量分别管理。系统监控在 Linux 下读取 `/proc`，GPU 数据还使用 `nvidia-smi` 和 PyTorch CUDA 接口。

## 常见问题

| 现象 | 检查方式 |
|---|---|
| 找不到共享库 | 回到项目根目录执行 `make interface`，确认 `build/libdraughts.so` 存在 |
| 无法启动窗口 | 检查当前桌面会话，运行 `python3 -m tkinter` 确认 Tk 与显示连接正常 |
| 中文显示不完整 | 确认系统具备中文字体；检查当前 Python 环境中的 Tk 字体支持。程序会尝试字体发现与回退 |
| 没有 CUDA 选项 | 检查当前 PyTorch 环境是否能识别 CUDA；可选择 CPU 运行 |
| 首步等待较久 | 核对搜索模拟次数和是否启用了编译；使用赛前已验证的设置 |
| AI 异常后没有继续 | 自动走棋已暂停；按弹窗处理后单步重试或恢复 |

## 支持边界

当前仅支持本地对局和鼠标点击走棋，没有网络对战、棋谱导入或崩溃恢复。和棋协商及拒和后的 40 步流程尚未实现，GUI 没有最大步数截断。

GUI 控制逻辑可通过 `make gui-test` 在无显示器环境中验证，已纳入 `make all-python-test`。它不替代桌面、CUDA 或外部打谱软件实机验证。维护入口见 [维护与验证](../docs/development.md)。
